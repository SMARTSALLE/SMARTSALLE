
CRÉER UNE APPLICATION FULL-STACK COMPLÈTE À PARTIR DE ZÉRO

NOM DE L’APPLICATION :
SmartSalle ISPITS

SOUS-TITRE :
Gestion intelligente des salles, des emplois du temps et des réservations — ISPITS Laâyoune

============================================================
1. OBJECTIF GÉNÉRAL
============================================================

Créer à partir de zéro une véritable application web professionnelle appelée :

SMARTSALLE ISPITS

L’objectif est de centraliser la gestion des salles, des réservations et des emplois du temps de l’ISPITS.

L’application doit permettre :

- de connaître les salles disponibles ;
- de connaître les salles occupées ;
- de réserver une salle ;
- d’éviter les doubles réservations ;
- de rechercher automatiquement une salle libre ;
- de gérer les options ;
- de gérer les groupes ;
- de gérer les modules ;
- de gérer les enseignants ;
- de gérer les réservations ;
- de gérer les emplois du temps ;
- de permettre aux coordinateurs de travailler simultanément ;
- de permettre à l’administration d’avoir une vision globale ;
- de synchroniser les changements en temps réel ;
- d’imprimer les emplois du temps ;
- d’exporter les données ;
- de conserver un historique des modifications.

Ce doit être une vraie application fonctionnelle et non une simple maquette.

============================================================
2. TECHNOLOGIE
============================================================

Construire une application Full-Stack moderne.

Utiliser les fonctionnalités natives disponibles dans Freebuff pour :

- Frontend
- Backend
- Base de données
- Authentification
- Stockage si nécessaire
- API
- Synchronisation temps réel
- Hébergement

Utiliser une architecture propre, sécurisée et évolutive.

La base de données doit être persistante.

NE PAS utiliser uniquement des données statiques ou localStorage pour les données principales.

Toutes les données importantes doivent être enregistrées dans la base de données.

18. CRITÈRES DE DISPONIBILITÉ
============================================================

- elle n’a pas de réservation qui chevauche le créneau demandé ;
- elle possède les équipements demandés si un équipement spécifique est requis.

- frontend
- backend
- base de données.

Même si deux utilisateurs réservent au même moment, la base de données doit empêcher le conflit.

51. RÈGLE CRITIQUE SUR LES CONFLITS
============================================================

Exemple :

09:00–11:00
09:30–10:30

mais permet :

10:00–12:00.
